# Supabase setup (for this repo)

This repo is a static website (HTML/CSS/JS) that uses:

- **Supabase Auth** (email + password) in the browser
- **Supabase Edge Functions** to serve **members-only** data
- A simple allowlist table (`allowed_members`) to decide who is “registered”

You will configure 4 things:

1) Create a Supabase project
2) Turn on Auth + set redirect URLs
3) Create DB tables
4) Deploy Edge Functions + set secrets

---

## 1) Create a Supabase project

1. Go to https://supabase.com → **New project**
2. Choose an organization
3. Project name: e.g. `yal-aiseries`
4. Set a strong database password
5. Pick a region close to your users

When the project is ready, open **Project Settings → API** and copy:

- **Project URL** (looks like `https://<project-ref>.supabase.co`)
- **anon / publishable key** (safe for browser)
- **service_role key** (SERVER ONLY — never put this in browser files)

---

## 2) Configure the frontend keys

This repo reads your URL + anon key from:

- [supabase-config.js](supabase-config.js)

Set:

- `window.SUPABASE_URL = 'https://<project-ref>.supabase.co'`
- `window.SUPABASE_ANON_KEY = 'sb_publishable_...'`

Do **not** put the service role key into any `.html` or `.js` that ships to the browser.

## 3) Enable email login + redirect URLs

In Supabase Dashboard:

1. **Authentication → Providers → Email**
  - Enable Email provider (email + password).
  - This site uses email+password for normal sign-in. Users only receive an email when setting/resetting their password.

2. **Authentication → URL Configuration**

Set:

- **Site URL**
  - Production (GitHub Pages): `https://yalaiseries.github.io/supabase`
  - Local dev: `http://localhost:5173`

- **Redirect URLs** (add ALL you need)
  - `https://yalaiseries.github.io/supabase/members.html`
  - `https://yalaiseries.github.io/supabase/winners.html`
  - `http://localhost:5173/members.html`
  - `http://localhost:5173/winners.html`

Why: the login email link will only redirect to allowlisted URLs.

Why: Supabase will only redirect account confirmation and password reset links to allowlisted URLs.

## 4) Create database tables

Open **SQL Editor** in Supabase and run:

You can also run the bundled schema file at [supabase/sql/schema.sql](supabase/sql/schema.sql).

### 4.1 Registered members allowlist

```sql
create table if not exists public.allowed_members (
  email text primary key,
  name text,
  source text,
  metadata jsonb,
  created_at timestamptz not null default now()
);
```

You’ll populate this either manually, or via the included webhook (Google Form → Edge Function).

Tip: keep `allowed_members` minimal (email + optional name). Store full survey responses elsewhere if needed.

### 4.2 (Optional) Members-only resources library

```sql
create table if not exists public.members_resources (
  id bigint generated by default as identity primary key,
  title text not null,
  url text not null,
  note text,
  sort_order int,
  active boolean not null default true,
  created_at timestamptz not null default now()
);

create index if not exists members_resources_active_sort
  on public.members_resources (active, sort_order, created_at);
```

Example content:

```sql
insert into public.members_resources (title, url, note, sort_order)
values
  ('Submission templates', 'https://example.com', '2-page write-up + 10-slide deck.', 10),
  ('Session recordings', 'https://example.com', 'Internal links for participants.', 20);
```

### 4.3 Winners content (private, stored in DB)

To keep the GitHub repo public **without leaking winners content**, winners data is stored in a table and served via the `winners` Edge Function (membership-gated).

```sql
create table if not exists public.winners_payload (
  year int primary key,
  payload jsonb not null,
  updated_at timestamptz not null default now()
);

create index if not exists winners_payload_updated_at
  on public.winners_payload (updated_at);
```

## 6) Link the project + set secrets + deploy functions

From the repo root:

```powershell
cd C:\2026_AI_Collaboration\aiseries
supabase login
supabase link --project-ref <your-project-ref>
```

Set secrets used by these Edge Functions:

```powershell
supabase secrets set SERVICE_ROLE_KEY=<your-service-role-key>

# For the registration webhook
supabase secrets set REGISTRATION_WEBHOOK_SECRET=<make-a-long-random-secret>

# For homepage Q&A (if you’re using it)
supabase secrets set OPENAI_API_KEY=<your-key>
supabase secrets set OPENAI_MODEL=gpt-4o-mini

# For winners content upload (server-side admin function)
supabase secrets set WINNERS_ADMIN_TOKEN=<make-a-long-random-secret>
```

Note: Supabase reserves secret names starting with `SUPABASE_`. The Edge Functions already have `SUPABASE_URL` and `SUPABASE_ANON_KEY` available in the runtime. You only need to set `SERVICE_ROLE_KEY` (and your other app secrets).

Deploy:

```powershell
supabase functions deploy members-resources
supabase functions deploy winners
supabase functions deploy winners-admin
supabase functions deploy chat
supabase functions deploy register-sync
```

## 7) Seed winners content (without committing to Git)

Winners content should be uploaded into `public.winners_payload` via the `winners-admin` Edge Function.

### 7.1 Create a JSON payload locally

Create a local JSON file (do **not** commit it) like `winners-2025.json`.

### 7.2 Upload via PowerShell

```powershell
$SUPABASE_URL = 'https://<project-ref>.supabase.co'
$ADMIN_TOKEN = '<your-WINNERS_ADMIN_TOKEN>'

# Example: upload 2025 payload
$body = @{
  year = 2025
  payload = (Get-Content -Raw -Path .\winners-2025.json | ConvertFrom-Json)
} | ConvertTo-Json -Depth 100

Invoke-RestMethod `
  -Method Post `
  -Uri "$SUPABASE_URL/functions/v1/winners-admin" `
  -Headers @{ 'content-type'='application/json'; 'x-admin-token'=$ADMIN_TOKEN } `
  -Body $body
```

Repeat for other years (e.g. 2024).

### 7.3 Verify the members-only API reads from DB

When logged in as an allowlisted user, the `winners` API should return `source: "db"` once rows exist in `public.winners_payload`.

## Notes / common gotchas

- If a confirmation or password reset link redirects to an error page: your **Redirect URLs** in Supabase are missing the exact URL.
- If a confirmation/reset email link sends you to `http://localhost:3000` (or any localhost URL): your **Authentication → URL Configuration** is still set to localhost. Update it to your real site URL, then re-send the email (old emails keep the old redirect).
- If you can log in but get “not registered”: your email is not in `allowed_members`.
- Keep the **service role key** secret. It is only used inside Edge Functions.

### “Registered” vs “Account” (important)

This system intentionally separates:

- **Account (can sign in)** — Supabase Auth user
  - View in Supabase Dashboard → **Authentication → Users**

- **Registered participant (can access members-only content)** — allowlist row
  - View in Supabase Dashboard → **Table Editor → allowed_members**

Your Google Sheet sync populates the allowlist. For a user-friendly password setup flow, participants use **Request access / set password** on the members page (same email). Supabase sends them a one-time link to set a password, then they can log in normally thereafter.

If a participant forgets their password later, they can use **Forgot password** on the members page to receive a reset email.

## 8) Link a Google Sheet to the allowlist ("Email address" column)

You shared a Google Sheet that contains registrations. To make **that sheet** automatically grant access to members-only content, the simplest approach is:

- Google Sheets **Apps Script** reads new rows
- It calls this repo’s webhook Edge Function: `register-sync`
- `register-sync` upserts into Supabase table `allowed_members`

### 8.1 Prerequisites

1. In Supabase, ensure you have created `allowed_members` (section 4.1).
2. Deploy the Edge Function `register-sync` (section 6).
3. Set the secret `REGISTRATION_WEBHOOK_SECRET` in Supabase (section 6).

### 8.2 Apps Script (copy/paste)

In your Google Sheet:

- **Extensions → Apps Script**
- Paste the script below
- Update `SUPABASE_FUNCTION_URL` with your project ref
- Set `WEBHOOK_SECRET` to match your Supabase secret
- Update `SHEET_NAME` if needed (or leave blank to use the active sheet)

```javascript
// Google Sheets → Supabase allowlist sync
// Reads the "Email address" column and calls the register-sync Edge Function.

const SUPABASE_FUNCTION_URL = 'https://<project-ref>.functions.supabase.co/register-sync';
const WEBHOOK_SECRET = '<REGISTRATION_WEBHOOK_SECRET>';

// Optional: set to a specific tab name. If blank, uses the active sheet.
const SHEET_NAME = '';

// Header names (must match your sheet header row)
const EMAIL_HEADER = 'Email address';
const NAME_HEADER = 'Name'; // optional; change if your sheet uses a different label

function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu('Supabase')
    .addItem('Sync new rows', 'syncNewRows')
    .addItem('Reset cursor (re-sync from top)', 'resetSyncCursor')
    .addToUi();
}

function getTargetSheet_() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  if (SHEET_NAME && ss.getSheetByName(SHEET_NAME)) return ss.getSheetByName(SHEET_NAME);
  return ss.getActiveSheet();
}

function normalizeEmail_(value) {
  return String(value || '').trim().toLowerCase();
}

function resetSyncCursor() {
  PropertiesService.getScriptProperties().deleteProperty('LAST_SYNC_ROW');
  SpreadsheetApp.getUi().alert('Cursor cleared. Next sync will start from the header row + 1.');
}

function syncNewRows() {
  if (!SUPABASE_FUNCTION_URL || SUPABASE_FUNCTION_URL.indexOf('<project-ref>') !== -1) {
    throw new Error('Set SUPABASE_FUNCTION_URL to your real project ref.');
  }
  if (!WEBHOOK_SECRET || WEBHOOK_SECRET.indexOf('<') !== -1) {
    throw new Error('Set WEBHOOK_SECRET to your real REGISTRATION_WEBHOOK_SECRET.');
  }

  const lock = LockService.getScriptLock();
  lock.waitLock(30 * 1000);
  try {
    const sheet = getTargetSheet_();
    const values = sheet.getDataRange().getValues();
    if (!values || values.length < 2) return;

    const header = values[0].map(String);
    const emailIdx = header.indexOf(EMAIL_HEADER);
    if (emailIdx < 0) throw new Error('Could not find header: ' + EMAIL_HEADER);

    const nameIdx = header.indexOf(NAME_HEADER);

    const props = PropertiesService.getScriptProperties();
    const lastSyncRow = Number(props.getProperty('LAST_SYNC_ROW') || '1');
    const startRow = Math.max(2, lastSyncRow + 1); // 1-based rows; row 1 is header
    const endRow = values.length; // 1-based

    let synced = 0;
    for (let rowNum = startRow; rowNum <= endRow; rowNum++) {
      const row = values[rowNum - 1];
      const email = normalizeEmail_(row[emailIdx]);
      if (!email) continue;

      const name = nameIdx >= 0 ? String(row[nameIdx] || '').trim() : '';

      const payload = {
        email: email,
        name: name,
        source: 'google_sheet',
        sheetId: SpreadsheetApp.getActiveSpreadsheet().getId(),
        sheetName: sheet.getName(),
        rowNumber: rowNum,
        row: row
      };

      const resp = UrlFetchApp.fetch(SUPABASE_FUNCTION_URL, {
        method: 'post',
        contentType: 'application/json',
        headers: { 'x-webhook-secret': WEBHOOK_SECRET },
        payload: JSON.stringify(payload),
        muteHttpExceptions: true
      });

      const code = resp.getResponseCode();
      if (code >= 200 && code < 300) {
        synced++;
        props.setProperty('LAST_SYNC_ROW', String(rowNum));
      } else {
        throw new Error('Row ' + rowNum + ' failed: HTTP ' + code + ' ' + resp.getContentText());
      }
    }

    SpreadsheetApp.getUi().alert('Sync complete. Added/updated: ' + synced);
  } finally {
    lock.releaseLock();
  }
}
```

### 8.3 Add an automatic trigger

In Apps Script:

- **Triggers (clock icon) → Add Trigger**
  - Choose ONE of these approaches:

**Recommended (near real-time) — if this is a Google Form responses sheet**

- Add this handler to your script (it pushes the newly submitted row immediately):

```javascript
function onFormSubmit(e) {
  // e.namedValues uses your column headers, e.g. "Email address"
  var values = (e && e.namedValues) ? e.namedValues : {};
  var email = (values[EMAIL_HEADER] && values[EMAIL_HEADER][0]) ? values[EMAIL_HEADER][0].trim() : '';
  if (!email) return;

  var name = (values[NAME_HEADER] && values[NAME_HEADER][0]) ? values[NAME_HEADER][0].trim() : '';

  var payload = {
    email: email,
    name: name,
    source: 'google_form',
    submittedAt: new Date().toISOString(),
    raw: values
  };

  UrlFetchApp.fetch(SUPABASE_FUNCTION_URL, {
    method: 'post',
    contentType: 'application/json',
    headers: { 'x-webhook-secret': WEBHOOK_SECRET },
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  });
}
```

- Then create an installable trigger:
  - Choose function: `onFormSubmit`
  - Select event source: `From spreadsheet`
  - Select event type: `On form submit`

**Fallback (polling) — if this is NOT a Form responses sheet**

- Create a time-driven trigger:
  - Choose function: `syncNewRows`
  - Select event source: `Time-driven`
  - Select type of time based trigger: `Minutes timer`
  - Select minute interval: every `1`–`5` minutes (choose `1` for closest to real-time)

The polling approach is simpler but not truly real-time; the form submit trigger is effectively real-time.

Tip: run `syncNewRows()` once manually first to authorize permissions, then rely on your trigger.
